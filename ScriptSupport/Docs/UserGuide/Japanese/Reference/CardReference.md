# カード 参照

## 1. 概要

Card Reference は、設定済みの Data Source からカード情報を検索・参照するための機能を提供します。

この機能では、主に次の 2 つの検索方法を利用できます。

- **カードテキスト検索:** 名前、説明、文字列を対象として、Card Text レコードを検索します。
- **カードスクリプト検索:** Lua スクリプトファイルの内容を検索します。

また、高度な検索を使用して、テキスト情報やカードの属性に基づいてカードを検索し、対応するカードテキストやスクリプトファイルを確認できます。

## 2. カードデータの読み込みの仕組み

Card Reference を使用する前に、Script Support が Data Source からカードデータを読み込み、どのように管理するかを理解しておくことをお勧めします。

### 2.1. Data Source

1 つの Data Source には、複数のデータベースファイルと複数のスクリプトファイルを含めることができます。

データの読み込み時、Script Support は既存のデータベースファイルを読み込んでカード情報を取得すると同時に、スクリプトファイルを検索するためのデータ構造を構築します。

読み込み処理によって、主に次の 2 種類のデータが生成されます。

- **カード情報:** データベースファイルから読み込まれた Card Data と Card Text が含まれます。
- **カードスクリプト:** Card ID と対応する Script File のパスを関連付ける検索用データ構造です。

### 2.2. YGO データベースの構造

標準的な YGO データベースでは、カード情報を保存するために次の 2 つの主要なテーブルを使用します。

| テーブル | 説明                                                         |
|---------| ------------------------------------------------------------|
| `datas` | `scope`、`type`、`race`、`attribute` などの属性を含む Card Data を保存します。 |
| `texts` | `name`、`desc`、`str1` ～ `str16` を含む Card Text を保存します。         |

これら 2 つのテーブルは、カード ID を表す `id` カラムによって関連付けられています。

### 2.3. YGO Game Engine の標準的な読み込み方式

YGO Game Engine は、標準では上書き方式（Overwrite）によってデータを読み込みます。

同じ ID を持つカードレコードが複数読み込まれた場合、後から読み込まれたレコードが、それ以前に読み込まれたカード情報を上書きします。

そのため、最後に読み込まれたバージョンの情報だけが保持され、参照可能になります。

### 2.4. Script Support のデータ読み込みロジック

Script Support では、上記の標準的な上書き方式を使用しません。代わりに、Card Data と Card Text をそれぞれ独立して処理します。

**Card Data**

- 各 Card ID につき、Card Data レコードを 1 件だけ保持します。
- 同じ Card ID を持つ Card Data レコードが複数ある場合、最初に読み込まれたレコードを保持します。
- それ以降に読み込まれた同じ ID のレコードは無視され、既存のデータを上書きしません。

**Card Text**

- 各 Card ID は、読み込まれた Text レコードを格納する `List<CardText>` を管理します。
- データベースから読み込まれた各 Text レコードは、対応するリストに追加されます。
- 言語、テキスト内容、その他の属性に基づく重複レコードのフィルタリングや削除は行いません。

そのため、同じ言語やまったく同じ内容を持つ場合でも、複数の Text レコードが同じ Card ID の下に共存できます。

この方式により、Script Support は既存のすべての Card Text を保持しながら、各 Card ID に対して 1 件の Card Data レコードを維持します。

### 2.5. カードスクリプトの読み込み

カードスクリプトは、個別のプレーンテキスト（Plain-text）Lua ファイルとして保存されます。

標準的なファイル名の規則は次のとおりです。

```text
c{id}.lua
```

例:

```text
c1001.lua
c1002.lua
c1003.lua
```

読み込み時、Script Support は次の検索用データ構造を構築します。

```csharp
Dictionary<ulong, List<string>> CardScripts;
```

この Dictionary は、次の情報を使用します。

- **Key (`ulong`):** Card ID。
- **Value (`List<string>`):** その Card ID に対応するファイルパスの一覧。

したがって、1 つの Card ID に複数の Script File を関連付けることができ、対応するすべてのパスがリスト内に保持されます。

このデータ構造により、Script Support は選択されたカードに関連するすべての Script File を検索し、表示できます。

## 3. カード検索

Card Reference では、`カードテキスト検索` と `カードスクリプト検索` の 2 つの検索方法を利用できます。

### 3.1. カードテキスト検索

`カード検索` フィールドでは、テキスト情報に基づいてカードを検索できます。

検索処理は、Data Source 内のすべてのカードについて、読み込み済みのすべての Card Text レコードを対象に実行されます。

検索対象のフィールドは次のとおりです。

| フィールド | 説明                |
|-----------|--------------------|
| `Name`    | カード名です。                  |
| `Desc`    | カードの説明および効果の内容です。 |
| `Str`     | カードの追加テキストです。        |

各 Card ID は複数の Card Text レコードを持つことができるため、検索処理では各カードの `List<CardText>` に読み込まれたすべてのレコードを確認します。

つまり、言語や他のレコードとの内容の重複に関係なく、カードが持ついずれかの Text レコードを通じて、そのカードを検索できます。

### 3.2. カードスクリプト検索

`スクリプト検索` フィールドでは、スクリプトファイルの内容に基づいてカードを検索できます。

`カード検索` とは異なり、`スクリプト検索` はデータベース内の Script フィールドを検索しません。代わりに、Data Source 内の Lua スクリプトファイルの内容から、指定されたテキスト文字列を検索します。

検索処理は、Data Source 内に存在するすべての Script File のパスを対象に実行されます。

各 Script File は独立したプレーンテキストファイルであるため、システムは各ファイルの内容を確認し、一致する結果を特定します。

### 3.3. 検索結果

どちらの検索方法でも、一致したカードはそれぞれの検索結果一覧に表示されます。

ユーザーは、次のマウス操作で検索結果を開くことができます。

| マウス操作      | 動作                   |
|----------------|-----------------------|
| 左クリック      | 選択した内容を一時 Tab で開きます。 |
| 左ダブルクリック | 選択した内容を固定 Tab で開きます。 |

カードテキスト検索では、カードを選択すると、そのカードに存在する Card Text が表示されます。

カードスクリプト検索では、検索結果を選択すると、対応するスクリプトの内容が開きます。

## 4. 高度な検索

高度な検索では、カードを検索するための追加条件を指定できます。

この領域は、カードテキスト、カードデータ、カード情報の 3 つのセクションに分かれています。

### 4.1. カードテキスト

カードテキストでは、テキスト情報に基づいてカードを検索できます。

現在、次の検索フィールドを利用できます。

| フィールド    | 説明                |
|-------------|---------------------|
| Card ID     | Card ID で検索します。   |
| カードの別名  | カードの別名で検索します。     |
| カード名     | カード名で検索します。       |
| カードの説明  | カードの説明内容を検索します。   |
| 文字列       | カードの追加テキストを検索します。 |

これらのフィールドを使用することで、通常のカードテキスト検索よりも具体的な条件を指定できます。

### 4.2. カードデータ

カードデータでは、カードの属性に基づいてカードを検索できます。

現在、次の検索属性を利用できます。

- Scope
- Type
- Race
- Attribute
- その他のサポート対象属性

このセクションは、テキスト内容ではなく、カードの特性や属性に基づいてカードを検索したい場合に便利です。

### 4.3. カード情報

カード情報では、現在選択されているカードの詳細情報を表示します。

利用可能なデータに応じて、次の情報が表示されます。

- カード名
- カードタイプ
- カード画像
- その他のカード情報

このセクションは検索条件を設定するためではなく、カード情報を参照するために設計されています。

## 5. カード情報の表示

カードを選択すると、Script Support はそのカードについて現在利用可能な情報を **Result Panel** に表示します。

### 5.1. カードテキスト

カードテキストは `Desc Result` Tab に表示されます。

表示される内容は、現在の Card ID に属する選択済みの Card Text レコードに対応します。

同じ Card ID に複数の Card Text レコードが存在する場合、ユーザーは表示するレコードを選択できます。

### 5.2. カードテキストのバージョン

Script Support は読み込まれたすべての Text レコードを保持し、上書きやフィルタリングによって削除しないため、1 つの Card ID に複数の Card Text レコードが存在する場合があります。

説明表示領域の上部にある ComboBox から、表示する Card Text レコードを選択できます。

選択対象は、読み込み済みデータに存在するレコードです。Script Support は、言語や内容の重複に基づいてレコードを自動的に識別、分類、または削除することはありません。

### 5.3. カードスクリプト

カードを選択すると、Script Support はそのカードの Card ID を使用して、`CardScripts` 内から対応する Script File のパスを検索します。

<!--

論理的な検索処理は、次のコードと同等です。

```csharp
if (CardScripts.TryGetValue(cardId, out var paths))
{
    // Display the corresponding Script Files.
}
```
-->

各パスは、それぞれ独立した Script File を表します。

対応するすべての Script File は `Script Result` に表示され、各ファイルは個別の TabItem で開かれます。

したがって:

- 1 つの Card ID に対応する Script File が 1 つの場合、Tab は 1 つ表示されます。
- 1 つの Card ID に対応する Script File が複数ある場合、複数の Tab が表示されます。
- Card ID に関連付けられた Script File が存在しない場合、表示する対応スクリプトはありません。
